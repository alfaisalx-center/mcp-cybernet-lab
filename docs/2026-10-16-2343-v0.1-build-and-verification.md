# v0.1 — what was built and how it was verified

16 October 2026. First version of mcpnet, from the design plan of the same day
(`2026-10-16-2305-mcp-testbed-yaml-generator-plan.md` in Ayman Ketat's supervision records).

## Built

- YAML schema (`mcpnet/schema.py`): trust domains, servers, clients, gateway, canaries, attacks,
  transforms, logging, seed. Unknown fields are errors. Later-milestone features are accepted by the
  schema and refused by `build` with the milestone name.
- Generator (`mcpnet/compose.py`): Dockerfiles, `docker-compose.yml`, one network per trust domain
  (`internal` unless `internet: true`), netem delay/jitter/loss, seeded canaries, pristine data copy,
  manifest.
- CLI: `validate`, `build`, `up`, `smoke`, `reset`, `down`.
- Minimal MCP probe (`mcpnet/probe.py`, standard library only), stdio and Streamable HTTP.
- Server packaging (`images/runtime/install_server.py`): any npm or PyPI MCP server becomes
  `mcp-<id>`; networked via mcp-proxy 0.13.0.

## Problems found and fixed

- `/sys/class/net` lists `bonding_masters`; netem now applies to `eth*` interfaces only.
- First probe after `up` could hit a server still starting; the HTTP probe retries while the port is closed.
- `mcp-server-sqlite` 2025.4.25 (archived) fails with the current `mcp` and `pydantic`
  (`Server` has no `list_resources`; missing `eval_type_backport`). Pinned with
  `with_packages: ["mcp==1.6.0", "pydantic==2.10.6"]`.
